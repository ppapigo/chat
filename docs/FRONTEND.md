# 프론트엔드

## 화면 사용

첫 화면에서 **계정 연결하기**를 선택해 Board 액세스 토큰을 입력합니다. 인증되면 채팅방 목록이 표시됩니다. 방을 선택하면 서버에 참여를 등록하고 실시간 대화·기록·참여자를 불러옵니다. **새 채팅방**은 생성 직후 해당 방으로 이동합니다.

- 방 목록은 서버 페이지를 20개씩 읽습니다. 갱신해도 이미 읽은 페이지 범위를 유지하며, 뒤늦게 도착한 이전 요청은 화면을 덮지 않습니다. 검색과 **지금 대화 중** 필터는 이미 불러온 목록에 적용합니다. 서버 전체 검색은 제공하지 않습니다.
- Enter는 전송, Shift+Enter는 줄바꿈입니다. 한글 조합 중 Enter는 전송하지 않습니다. 빈 메시지와 1000자 초과 입력은 막습니다.
- 전송한 메시지는 서버에서 돌아온 후 표시합니다. 전송 확인 전에는 중복 전송을 막고 입력을 보존합니다. 확인 실패 때 자동 재전송하지 않습니다.
- **이전 메시지 불러오기**는 메시지 ID 커서로 더 오래된 50개를 읽습니다. 스크롤 위치를 보존합니다. 화면 아래를 보고 있으면 새 메시지에 따라 스크롤하고, 과거를 읽는 중이면 **새 메시지 ↓** 버튼으로 이동합니다.
- 다른 방으로 이동할 때 작성 내용은 방별 메모리에 남습니다. 새로고침·연결 해제 때 제거됩니다. 방 전환은 기존 방의 DB 참여를 유지합니다.
- 참여자 패널에서 **채팅방 나가기**를 선택하면 DB 참여를 삭제합니다. 개설자에게만 **채팅방 삭제**가 보이며 서버도 권한을 확인합니다. 삭제 전에는 영구 삭제를 안내합니다.
- 데스크톱은 목록·대화·참여자의 3열 배치입니다. 1180px 이하에서 참여자 목록은 버튼으로 열고, 760px 이하에서 채팅방 목록도 별도 패널로 엽니다.
- 좌측 계정 버튼에서 연결된 이메일을 확인하거나 연결을 해제합니다. 화면 연결 해제는 Board 로그아웃이나 JWT 폐기가 아닙니다.

**화면 둘러보기**는 `DemoApi`/`DemoTransport`를 쓰는 별도 모드이며 상단에 예시 데이터임을 표시합니다. 서버 통신을 하지 않고 메모리에서만 변경합니다. **실제 계정 연결** 버튼으로 예시 상태를 제거하고 실제 인증으로 이동합니다.

## 파일 구조

| 파일 | 책임 |
| --- | --- |
| `frontend/index.html` | 화면 구조, SVG 심볼, 네이티브 dialog, 접근성 레이블 |
| `frontend/assets/styles.css` | 색상·배치·반응형·focus·reduced motion |
| `frontend/assets/js/app.js` | 화면 상태, 이벤트, API 흐름, 메시지 표시 |
| `frontend/assets/js/api.js` | fetch, Bearer 헤더, 15초 제한, 응답·오류 해석 |
| `frontend/assets/js/transport.js` | STOMP 연결·재연결·구독·전송 |
| `frontend/assets/js/core.js` | 토큰 정규화, URL, 메시지 병합, 검색, 검증 |
| `frontend/assets/js/demo.js` | 실제 API와 같은 인터페이스의 인메모리 예시 |
| `frontend/assets/vendor/` | 고정 버전 STOMP 번들과 Apache 2.0 라이선스 |
| `frontend/package.json` | 프론트엔드 의존성과 실행·테스트 명령 |
| `frontend/tools/preview.mjs` | localhost:4173의 정적 검토 서버 |
| `frontend/tools/vendor.mjs` | npm 패키지에서 번들·라이선스 복사 |
| `frontend/tools/integration-test.mjs` | 실제 Spring Boot/브라우저 통합 검증의 Gradle 실행 |
| `frontend/tests/` | 단위·브라우저 회귀·실제 서버 연동 테스트 |

사용자 요구에 따라 프론트엔드는 HTML·CSS·일반 JavaScript로 작성합니다. 직접 작성한 화면 코드는 `.js`, 개발 도구와 테스트는 `.mjs`이며 TypeScript 소스·컴파일러·tsconfig가 필요하지 않습니다. 프레임워크와 번들러를 추가하지 않아 기존 Spring Boot 프로젝트에서 바로 동작합니다. 폰트는 시스템 한글 폰트로 fallback하며 외부 폰트·CDN 요청을 하지 않습니다. 디자인 그림과 아이콘은 CSS/SVG로 구성했습니다.

`frontend/`가 소스 기준이며 별도의 정적 사본은 관리하지 않습니다. Gradle은 `index.html`과 `assets/`만 서버 리소스로 복사합니다. 의존성·잠금 파일은 루트 npm workspace로 관리합니다. 루트에서 `npm ci`로 설치하고 루트 또는 `frontend/`에서 미리보기·테스트 명령을 실행할 수 있습니다. 설치 없이 화면만 보려면 `cd frontend` 후 `npm run preview`를 실행하세요.

## 상태와 비동기 처리

`state`가 API, 소켓, 이메일, 방 목록, 활성 방, 메시지, 참여자, pagination, 임시 작성 내용을 관리합니다. `session`/`selection` 세대 번호로 연결 해제나 방 이동 후 돌아오는 이전 응답이 현재 화면을 덮지 않게 합니다.

접속 상태는 연결 전·연결 중·실시간 연결·재연결 중으로 표시합니다. 메시지 입력은 방 기록이 준비되고 실시간 연결이 완료되어야 활성화합니다. 방 가입과 기록 로딩 중에는 중복 선택을 막습니다. 실패한 기록은 방 안에서 다시 불러올 수 있습니다. 인증 오류는 토큰·화면 데이터를 비우고 재연결 dialog로 안내합니다. 계정 연결 창을 닫으면 진행 중인 인증 요청도 AbortController로 취소해 늦은 응답이 연결을 시작하지 못하게 합니다.

메시지는 서버 ID를 기준으로 중복을 제거하고 오름차순으로 병합합니다. 방 구독 후 기록을 읽으므로 실시간 이벤트와 이력 응답이 겹쳐도 하나만 표시합니다. 재연결하면 마지막으로 알고 있던 메시지까지 최신 페이지를 반복 조회해 50개 이상의 누락도 복구합니다. STOMP 클라이언트의 `onConnect`마다 구독을 복구하는 방식은 [공식 STOMP.js 문서](https://stomp-js.github.io/guide/stompjs/using-stompjs-v5.html)를 따릅니다.

## 인증·접근성

- 토큰은 `ChatApi`와 STOMP 연결 헤더에만 메모리로 보관합니다. localStorage, sessionStorage, 쿠키, URL, 콘솔 로그에 저장하지 않습니다. 토큰 입력 dialog를 닫으면 입력값도 제거합니다.
- 서버 응답의 이름·소개·내용은 `textContent`로 표시합니다. 사용자 HTML이나 스크립트를 삽입하지 않습니다.
- 모든 아이콘 버튼에 이름을 제공하고, 필터는 `aria-pressed`, 메시지 목록은 `role=log`, 접속·안내는 live region을 사용합니다.
- 네이티브 `<dialog>`가 모달 focus와 Escape 처리를 제공합니다. 입력 label, focus-visible outline, reduced motion 지원을 포함합니다.
- 화면의 개설자 여부 판단은 사용성 목적입니다. 인증·참여·삭제 권한의 최종 판단은 서버가 합니다.

## 변경 방법

색상은 `styles.css`의 `:root` 변수를 먼저 바꿉니다. API 확장은 `api.js`에 메서드를 추가하고 실제 DTO와 `demo.js`를 함께 맞춥니다. 새로운 STOMP 목적지는 서버 인터셉터의 허용 규칙과 `transport.js`를 함께 수정합니다. 실제 인증 토큰은 테스트 fixture나 스크린샷에 넣지 마세요.

외부 origin에서 별도 SPA로 배포하거나 sub-path 아래에 올리려면 현재 절대 경로(`/assets`, `/api/chat`, `/ws`)와 REST CORS, proxy 설정을 함께 변경해야 합니다. 기본 배포는 호스트 루트의 같은 origin입니다.
